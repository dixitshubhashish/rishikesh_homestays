# Languages (in-browser translation)

The one home for how the site is translated and how every language is kept in step with the English. Owner decisions: 23 languages (English + 22), Hindi first in the picker, never Urdu or Arabic; **one English page per URL, translated in the browser** (no `/hi/` copies); translate **every section** except the **"Rishikesh Homestays" name and logo**, the **contact forms** and the **proper nouns in stay names** (owner, 2026-10-06).

## Files (few, flat, one key per text)

| File | What | Written by |
|---|---|---|
| `i18n/en.json` | every English text the site shows: `{ "site": { id: English }, "stays": { id: English }, "rendered": [English…] }` | `scripts/i18n/extract.mjs` (never hand-edit) |
| `i18n/<lang>.json` | that language's translations: `{ id: translation }`, one entry per text | translators via `scripts/i18n/sync.mjs merge` |
| `i18n/dist/<lang>.json`, `i18n/dist/<lang>.stays.json` | what the browser fetches: `{ "s": { id: text }, "p": [[English pattern, text], …] }` | `scripts/i18n/build-runtime.mjs` (never hand-edit) |
| `i18n/STYLE.md` | each language's house style: register (आप, du, tú…), glossary, names kept in Latin script | people and agents, by hand |

**Ids**: the first 11 base64url characters of SHA-256 of the normalised English (66 bits). The same text has the same id on every page, in every file and in every future run, so it is stored and translated once and found directly (no lookup tables, no random keys). `scripts/i18n/catalog.mjs` makes them in Node; `segId()` in `assets/js/i18n-runtime.js` makes the same ones in the browser (a synchronous SHA-256; a test checks both against `node:crypto`). Adding a text whose id is already taken by a different text stops the build (`addText`).

**Sections**: `site` = the 15 hand-made pages (text, `<title>`, meta description, alt/title/aria-label/placeholder, the hero slider's `data-captions`/`data-headlines`/`data-copy`, JSON-LD prose), the footer-stays block, and text written by scripts. `stays` = the generated stays pages (only those pages load `<lang>.stays.json`). `rendered` = texts `extract-rendered.mjs` found in the browser that the source scans miss; `extract.mjs` adds them to `site`.

## How a page gets translated

1. **Head snippet** (`rh-i18n`, written by `scripts/i18n/snippet.mjs` into the hand-made pages and `thanks.html`, whose head the stays pages copy): picks the language from `?lang=xx`, else `localStorage['rh-lang']`, else English; sets `<html lang dir>`; for a non-English language hides the body for at most 1.5 s and loads `assets/js/i18n-runtime.js`.
2. **Runtime** fetches `i18n/dist/<lang>.json` (and on `/hotels/…` stays pages also `<lang>.stays.json`), walks the page the way the extractor does (runs of inline content with `<0>…</0>` placeholders), swaps in translations reusing the original elements (links and listeners keep working), and keeps a `MutationObserver` so text scripts add later (hero slider, nav drawer, stays lists and filters, the stay page, popups, the 404 countdown, site search) is translated too. It adds `lang` to every `/api/contact` POST (`page_lang`).
3. **Patterns**: a text with `{slots}` matches by shape. `{n1}`… only take digits (a number never swallows a trailing comma or period); any other slot takes text, and a slot value with its own entry (a city, area or category) is translated too; a stay name in a slot gets its generic words translated (below).
4. **Stay names** (`.sx-name`, `[data-stay-name]`): never translated as a whole, but their generic words are (`NAME_WORDS` in the runtime: Hotel, Guest House, Lodge, Resort, Camp, Hostel, Villa, Apartment, Cottage, Inn, Dharamshala, Rooms, Suites, B&B…): "Hotel Ganga View" → "होटल Ganga View". Proper nouns and institutions stay as written.
5. **Picker** (`assets/js/modules/lang-picker.js`): a small pill in the header (globe + two-letter code; the list shows every language in its own script) and one in the phone menu drawer. `assets/js/modules/nav-fit.js` shrinks the desktop nav text when a language's labels would push the header past one row.

**Never translated** (`NO_TRANSLATE`, identical in the runtime and `extract.mjs`, a test checks): `translate="no"`, `.notranslate`, every `<form>` except the homepage search filter (`data-search-form`), `.brand`, `.site-logo`, `.rhs-footer-logo`, stay names (except their generic words), the map attribution, the picker's code. Also never: prices, phones, emails, URLs, `href`/`value`/other `data-*`, street addresses (`translate="no"` on the stay page), the WhatsApp prefilled message and enquiry fields. Whole strings in `DO_NOT_TRANSLATE` (brand and platform names) are not even extracted.

## Where the English comes from

- **Hand-made pages**: `extract.mjs` (`extractPage`, the same walk as the runtime).
- **Footer stays links**: `extract-footer.mjs` (the `<!-- footer-stays -->` block of `thanks.html`).
- **Text in JavaScript**: `extract-ui.mjs`, a reviewed heuristic over `UI_FILES` (sentences and capitalised labels in string literals; owner-only text like the WhatsApp message excluded), plus month/day names and `NAME_WORDS`.
- **What the browser renders**: `extract-rendered.mjs` opens stay pages (both cities, a Google Maps stay, the not-found view), stays lists with a filter clicked, home with the WhatsApp drawer open and `/homestays` in a headless browser, walks them with the runtime, and keeps what no catalogue covers (numbers and known names turned into slots). It starts its own `server.js` on port 3917 and never posts a form. Run it (`npm run i18n:rendered`) after changing a script that writes text.
- **Generated stays pages**: `extract-stays.mjs` turns the ~44,000 sentences of `hotels/` into ~1,750 templates: numbers → `{n1}`…, known names → `{t1}`… (cities, categories, areas, kinds, landmarks from `landmarks.tsv`, search phrases from `search-pages.tsv`, the `AREA_NOTES` descriptions of `build_pages.py`: the **terms**, translated once on their own; and stay names). Stay rows, JSON-LD, og/twitter tags and the footer are left out.

## Keeping every language in sync

The ids hash the English, so a changed sentence simply shows up as missing in every language. **After any English text change** (a page, a JS message, the stays scripts):

```bash
npm run i18n:extract                                   # refresh i18n/en.json
npm run i18n:status                                    # per language: what is missing (site / stays)
node scripts/i18n/sync.mjs jobs <dir> [--size 45000] [--only hi,de]   # job files for translators
#   translate: each <dir>/<lang>-<n>.json -> <dir>/<lang>-<n>.out.json  { "<id>": "<translation>" }
node scripts/i18n/sync.mjs merge <dir> --dry           # checks placeholders, slots, numbers; lists rejects
node scripts/i18n/sync.mjs merge <dir>                 # writes the good ones into i18n/<lang>.json
node scripts/i18n/sync.mjs prune                       # drop translations whose English is gone
node scripts/i18n/build-runtime.mjs                    # rebuild i18n/dist/ (npm run build:i18n = extract + build)
npm run i18n:check                                     # exit 1 if any language misses anything
node scripts/i18n/sync.mjs suspect --only hi           # translations whose numbers differ (10:00 PM -> 22:00): glance at them
```

- `npm run build:stays` ends with the search index and `npm run build:i18n`; `.github/workflows/stays-refresh.yml` runs `build:i18n` too, so the English catalogue always matches the built pages. New stays templates show in English until translated: check `npm run i18n:status` after changing the stays scripts.
- `tests/integration/i18n-sync.test.js` (in `npm test`) fails when `en.json`'s `site` section is out of date, when any language lacks a site text, when the file layout drifts (extra folders, `qa-*` files), when ids are not content hashes, when the runtime and the extractor disagree on what is never translated, or when the language lists differ. `tests/integration/i18n-runtime.test.js` checks the head snippet and that `i18n/dist/` has the two files per language; `tests/modules/i18n-runtime.test.js` checks the browser SHA-256, the walk and the patterns.

### Translator rules (the merge enforces 1–3)

1. Keep every `<0>`, `</0>`, `<1/>` placeholder; text inside a pair stays inside it.
2. Keep every `{n1}`/`{t1}`/`{p}` slot exactly once (reorder freely); grammar must fit any city, area, category or stay name in a `{t}`.
3. Keep every English number in Western digits; extra numbers are fine (Japanese 1月, Hindi "91 लाख").
4. Follow the language's section of `i18n/STYLE.md` and reuse wording from `i18n/<lang>.json`. Brand and platform names stay as written.
5. Local-guide voice in the register the house style sets; quirky or sarcastic English stays quirky (rewrite the joke so it lands); no added facts, dates or "official" claims (copy rules in `docs/HANDOFF.md`).
6. Single generic words (`NAME_WORDS`) are read inside stay names: give the word as it reads in a hotel's name.

## Adding a language

Add the code to `LANGS` in `scripts/i18n/catalog.mjs`, to the head snippet (`scripts/i18n/snippet.mjs`, then run it; right-to-left languages also go in its RTL list) and to `LANGUAGES` in `assets/js/modules/lang-picker.js`; add its section to `i18n/STYLE.md`; then `sync.mjs jobs` → translate → `merge` → `build-runtime.mjs`.

## Adding a page

Add it to `PAGES` in `scripts/i18n/extract.mjs`, run `node scripts/i18n/snippet.mjs`, then the sync steps.
